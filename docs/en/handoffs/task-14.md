# Phase 14 — Feature readiness and reviewed round populations

Document-ID: EA-HANDOFF-14 · Revision: 2 · Language: en

`election_audit.features` publishes a disk-backed `feature-release-v1` from completed Phase 12 verification artifacts or immutable legacy derivatives. Verification inputs require the producer's final artifact checksum. The reader recognizes content verification separately from signature certification; it never upgrades an old release's eligibility. Counts, candidate destinations, omitted zeros and special categories retain their source meaning. Only reconciled, complete and legally supported counts produce electoral ratios.

The catalog `features.sqlite` has `units`, `counts`, `members`, `links`, `features`, `operations` and `comparisons`. Units carry `unit_key`, round/geography, principal/location IDs, nullable reviewed stable location, source snapshot and source readiness. The long feature table has typed scalar values/numerators/denominators plus readiness, reason and full JSON payload. All 21 registry families retain rows, including unavailable inferential, clock and corroboration inputs. Count, proportion and indicator units remain distinct. Partitioned Parquet uses round/UF partitions and bounded 2048-row groups. `manifest.json` pins the catalog, every partition, producer/registry versions and source identities.

`publish_features(electoral, output, links=None, operations=(), candidate_a=None, candidate_b=None, ufs=None)` is the Python entry point; `features_main` is the CLI adapter. Output directories must be new. Reviewed links use `reviewed-feature-links-v1`, exact location IDs, stable IDs, verified assertions and hash/record anchors. Whole-principal members must be disjoint and identical across rounds; composition, transfers and electorate require explicit review. Round totals and candidate vectors are aggregated before comparison; individual transfers remain unavailable.

Real AC content-verified run: `data/phase14/ac-content-verified`, 2270 principals and 54480 feature rows. `data/phase14/ac-location-development` additionally groups 668 same-round official polling locations using exact archived BWEB record anchors in `data/phase14/ac-round2-location-links.json`. This grouping is explicitly round-scoped development evidence, not a cross-round identity assertion. The initial release IDs and measured counts are in their immutable manifests. Later code adds separate ledger/accounting/signature components; regenerate into a new directory to obtain those additional rows. Root may continue to use the initial content-verified numeric measures because their definitions are unchanged.

Seven regression tests pass: all families, zero versus unknown, missing legal destinations, exceptional categories, duplicate conflicts, reviewed whole-member matching, electorate changes and overlapping-principal rejection. Ruff checks/format and paired documentation checks pass. The actual AC ratios are available, while model calibration, national inference, timings and signature/corroboration measures remain unavailable. Legacy-source AC capture can be slower because it validates the entire parent chain; it is not used to claim newly verified counts.

Limits: first-round electoral results, national features, geographic boundaries/TSE–IBGE crosswalk, and completed operational attendance/copy review are not supplied by this phase. Operational files are consumed only when declared and checksummed by their manifest. No dashboard outcome export is automatic: Phase 15 must publish an access-filtered view and protect untouched units. Later cross-round aliases must preserve existing inspection history.

Next: Phase 15 consumes the catalog and reviewed round-scoped AC links, freezes protocol and inspected-location history; Phase 16 fits only eligible released development inputs. Root owns CLI/recipe wiring. Existing raw data and releases remain unchanged.

Compatibility follow-up: 374 early preserved Phase 12 records lack the explicit member array. The reader now recovers principal plus slash-delimited aggregated members from the preserved `composition_raw`, validates unique codes, and rejects conflicts when both representations exist. Blank-source tokens mean no additional aggregated members; not-recorded tokens retain unknown composition. Existing AC feature/protocol artifacts are unchanged and remain unavailable for cross-round comparison; new publications use this versioned producer with its pinned code hash. Nine feature tests pass, including an immutable legacy aggregate fixture and conflicting composition representations.
